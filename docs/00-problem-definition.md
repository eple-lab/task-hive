# 00. 문제 정의서

작성일: 2026-11-17 · AIFFEL 「AI 이해하고 사용하기」 메인 퀘스트 2 제출용 · 근거: [D-33, D-34](02-decisions.md)

## 1. 도메인

**개인의 하루 정리와 할 일 관리.** 저녁에 하루를 돌아보며 내일 이후 할 일을 정하고, 한 일을 기록하는 일이다. 대상은 일정·할 일·일기를 각각 다른 도구에 적는 개인이다.

## 2. 현재의 문제

지금은 직접 만든 `todo` 앱에 할 일을 손으로 입력한다. 제목, 마감일, 하위 태스크를 하나씩 넣는다. 불편한 점은 네 가지다.

| 문제 | 설명 |
|---|---|
| 할 일을 떠올리는 것 자체가 일이다 | 할 일 앱은 이미 아는 할 일을 적는 도구다. 빈 입력창 앞에서 무엇을 적을지 떠올리다가 빠뜨린다 |
| 하루 끝에 적기 귀찮다 | 저녁에는 피곤해서 앱을 열고 제목·날짜·하위 항목을 하나씩 넣는 일을 미루게 된다 |
| 캘린더·일기·할 일이 흩어져 있다 | 일정은 캘린더에, 할 일은 앱에, 하루 기록은 또 다른 곳에 있어 한곳에서 돌아보기 어렵다 |
| 진행 상황 업데이트를 잊는다 | 끝낸 일을 체크하러 앱에 다시 들어가지 않아 목록이 실제와 달라진다 |

## 3. 개선 가설

**하루를 말하듯 적는 대화 안에 AI를 넣으면, 할 일을 떠올리고 옮겨 적는 일이 줄어든다.**

| 단계 | 지금 | AI를 넣으면 |
|---|---|---|
| 떠올리기 | 사람이 혼자 떠올린다 | AI가 하루 이야기를 들으며 "이건 할 일로 담아 둘까요?"라고 묻는다 |
| 옮겨 적기 | 제목·날짜·하위 항목을 손으로 입력 | AI가 대화에서 제목·날짜·하위 항목을 뽑아 후보로 보여 주고, 사람은 고르기만 한다 |
| 모아 보기 | 캘린더, 앱, 일기를 따로 연다 | 캘린더 일정을 후보로 가져오고, 대화를 요약해 일기로 남긴다 |
| 진행 갱신 | 앱에 다시 들어가 체크 | 대화에서 "그건 한 것 같아"라고 하면 체크된다 |

수업의 업무 유형으로는 **입력과 전사**(말한 것을 할 일 형식으로 옮겨 적기)에 가깝다. 이 유형은 효과가 직접적이지만 틀려도 그럴듯해 보여 알아채기 어렵다. 그래서 두 가지를 설계에 넣었다.

- AI가 뽑은 것은 **후보**일 뿐이고, 사람이 "담기"를 눌러야 등록된다.
- 후보마다 **근거가 된 대화 문장**을 함께 보여 준다.

AI를 넣지 않는 곳: 태스크 삭제(대화로 지울 수 없다), 일기 저장(요약을 보여 주고 "등록해"를 받아야 저장한다). 되돌리기 어려운 일은 사람이 정한다.

## 4. 대상 사용자

| 사용자 | 얻는 것 |
|---|---|
| 나 (eple) | 저녁에 대화 한 번으로 할 일 정리와 일기가 끝난다 |
| 할 일 앱을 깔아 두고 안 쓰게 되는 사람 | 입력창 대신 대화로 시작한다 |

## 5. 성공 기준

만들기 전에 정했다(2026-11-17). 가상 저녁 대화 20건으로 잰다.

| 기준 | 숫자 | 근거 |
|---|---|---|
| 놓치지 않은 비율 | 대화 속 할 일의 **80% 이상**을 뽑는다 | 4B급 작은 모델에 현실적인 선 |
| 지어낸 할 일 | 20건 전체에서 **3개 이하** | 지어낸 것은 사람이 지워야 한다 |
| 할 일이 없는 대화 | 3건 중 **2건 이상**에서 아무것도 뽑지 않는다 | "없다"고 답할 수 있어야 한다 |
| 등록 시간 | 손으로 `todo` 앱에 넣을 때보다 **짧다** | 기준선 |

- 현행 수준(손으로 넣을 때의 시간과 놓친 개수)은 아직 재지 않았다. 검증할 때 먼저 잰다.
- 기준을 못 넘으면 못 넘었다고 적고 이유를 분석한다.

## 6. 기존 방식 (기준선)

직접 만든 `todo` 앱에 손으로 입력한다. 같은 가상 대화 20건을 읽고 할 일을 직접 넣으면서 시간, 누른 횟수, 놓친 개수를 잰다. 기록 틀은 `eval/baseline_template.md`.

## 7. AI 모델 후보

실행 위치가 달라 성격이 다른 후보를 골랐다.

| 후보 | 실행 위치 | 고른 이유 |
|---|---|---|
| Qwen 4B급 양자화 모델 | Colab GPU | 수업의 `llm-chatbot`에서 써 본 모델. 대화가 본인 Colab으로만 간다 |
| llama3.2 | 내 PC의 Ollama (GPU 없음) | `honey-voice-log`에서 써 본 모델. 대화가 PC 밖으로 나가지 않는다 |
| 손 입력 | 사람 | 기준선 |

통과/탈락 조건(점수보다 먼저 본다): 대화를 외부 AI 회사로 보내지 않는다 / 라이선스가 과제 용도를 허용한다 / 한국어가 된다 / 정해진 JSON 형식으로 답한다.

말하기(TTS)는 브라우저 내장 음성으로 먼저 완성한다. Colab TTS 모델 비교는 [PoC-02](poc/poc-02-tts-korean-voices.md)로 남겼다.
