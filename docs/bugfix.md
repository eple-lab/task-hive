## BUG-001

**로그아웃 후 로그인 화면에 이전 이메일이 남음**

| 항목 | 내용 |
|---|---|
| 발견 | 2026-10-31, Render 운영 서버에서 회원가입 → 로그아웃 (eple) |
| 영향 | Supabase 모드 화면. 같은 컴퓨터를 다른 사람이 쓰면 직전 사용자의 이메일이 보인다 |
| 심각도 | 낮음 (비밀번호·토큰은 남지 않음) |
| 파일 | [public/app.js](../public/app.js) `showApp()` |

### 재현
1. 로그인 화면에서 이메일·비밀번호 입력 → 회원가입(또는 로그인)
2. 할 일 화면에서 **로그아웃**
3. 로그인 화면 이메일 칸에 1번의 이메일이 그대로 있다

페이지를 새로고침한 뒤 로그아웃하면 칸이 새로 그려져서 재현되지 않는다. **같은 페이지에서 로그인 → 로그아웃**할 때만 생긴다.

### 원인
로그인에 성공하면 `showApp()`이 화면을 할 일 화면으로 바꾸는데, 로그인 폼은 숨기기만 하고 **비밀번호 칸만 비웠다**. 숨겨진 이메일 칸에 값이 남아 있다가, 로그아웃 때 `showAuth()`가 폼을 다시 보여 주면서 그대로 드러났다.

### 수정
`showApp()`에서 이메일 칸도 비운다.

```js
// 2026-10-31 버그 수정: 이메일 칸도 비운다. 안 비우면 로그아웃 후 로그인 화면에 이전 이메일이 남는다 (docs/bugfix.md BUG-001)
$('auth-email').value = '';
$('auth-password').value = '';
```

`showAuth()`에서 지우지 않은 이유: 로그인 실패나 세션 만료(401)로 로그인 화면에 돌아올 때는 입력해 둔 이메일을 남기는 편이 편하다. 지울 시점은 **로그인에 성공해 폼을 떠날 때**가 맞다.

### 확인
페이지 안에서 `fetch`를 가짜 응답으로 바꿔 로그인 → 로그아웃만 실행했다. 실제 계정 정보는 네트워크로 보내지 않았다.

| 대상 | 로그아웃 후 이메일 칸 |
|---|---|
| 수정 전 (Render) | `mock@example.com` 남음 |
| 수정 후 (로컬) | 빈 칸 |
