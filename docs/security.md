# 보안

강의에서 배운 보안 원칙이 이 앱에 어떻게 적용됐는지 정리했다.

## 요약

| 위험 | 대응 | 위치 |
|---|---|---|
| SQL 주입 | 모든 값은 `?` 자리표로 따로 전달 (파라미터화 쿼리) | `db.js` |
| 화면 조작 (프론트는 못 믿는다) | 같은 규칙을 백엔드에서 다시 검사 | `server.js` |
| 스크립트 주입 (XSS) | 사용자 입력은 `textContent`로만 화면에 넣기 | `public/app.js` |
| 비밀값 유출 | `.env`에 두고 Git 제외 | `.gitignore` |
| DB 파일 유출 | `data/`는 Git 제외, 웹으로 내보내는 `public/` 밖에 둔다 | `.gitignore`, `db.js` |
| 내부 정보 노출 | 예상 못 한 에러는 "서버에서 문제가 생겼습니다."로만 응답 | `server.js` |
| 큰 요청 | 요청 본문 10KB, 제목 200자 제한 | `server.js` |

## SQL 주입 (SQL Injection)

사용자가 친 글자를 SQL 문장에 이어 붙이면, 글자가 명령으로 실행될 수 있다(xkcd "Little Bobby Tables").

```js
// ❌ 위험: 입력이 SQL 문장의 일부가 된다
db.exec(`INSERT INTO todos (title) VALUES ('${title}')`);

// ✅ 이 앱의 방식: SQL 문장과 값을 따로 전달한다
db.prepare('INSERT INTO todos (title, due_date) VALUES (?, ?)').run(title, dueDate);
```

### 검증한 것
| 입력 | 결과 |
|---|---|
| 제목에 `x'); DROP TABLE todos;--` | 그 글자 그대로 제목으로 저장됨. 표는 멀쩡함 |
| 검색에 `' OR 1=1 --` | 결과 0건 (모든 데이터가 나오지 않음) |
| 검색에 `50%`, `a_b` | `%`, `_`를 와일드카드가 아니라 글자로 찾음 |

### 문자열을 이어 붙이는 SQL이 딱 두 군데 있는 이유
`db.js`에는 템플릿 문자열로 만든 SQL이 있지만, 들어가는 값은 **사용자 입력이 아니다.**
- `${AUTO_DELETE_DAYS}`: 코드에 고정된 숫자 90
- `${placeholders}`: `?, ?, ?`처럼 자리표 개수만 만든 것. 실제 값은 여전히 따로 전달

## 프론트는 못 믿는다

화면의 검사(지난 날짜 막기, 완료된 할 일을 라디오에서 빼기 등)는 개발자 도구로 쉽게 우회된다.
그래서 모든 규칙을 `server.js`에서 다시 검사한다. 예: 화면을 거치지 않고 완료된 할 일에 태스크를 보내도 `409`로 거절된다.
전체 목록은 [business-rules.md](business-rules.md).

## 스크립트 주입 (XSS)

제목에 `<script>`나 `<b>` 같은 태그를 넣어도 HTML로 해석되지 않고 글자 그대로 보인다.
`app.js`는 `innerHTML`을 쓰지 않고, 화면 요소를 만들어 `textContent`로 글자를 넣는다.

## 비밀값과 파일

- `.env`: 길 A에는 비밀값이 없지만(포트, DB 위치), 길 B의 Supabase 키는 여기에 둔다. Git 제외.
- `.env.example`: 항목 이름만 적은 견본. Git에 올린다.
- `data/todo.db`, `*.db-wal`, `*.db-shm`: 실제 데이터. Git 제외.
- 저장소를 처음 올리기 전에 커밋 이력 전체에 `.env`나 `.db`가 없는지 확인했다.

## 개인정보

길 A는 개인정보를 모으지 않는다(할 일 제목만 저장).
길 B에서 로그인이 생기면 이메일이 저장된다. 그때의 원칙:
- 로그인은 직접 만들지 않고 **Supabase Auth**를 쓴다(비밀번호 해시·세션 관리는 검증된 도구에 맡긴다).
- 필요한 것만 모은다: 이메일 하나.
- RLS로 **자기 할 일만** 조회·추가·수정·삭제할 수 있게 한다. 다른 계정으로 시험해서 확인한다.
- Supabase 키 중 `service_role` 키는 RLS를 무시하므로 화면 코드에 절대 넣지 않는다.
