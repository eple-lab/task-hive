# 오늘의 회고

강의 "오늘의 회고" 질문에 답하는 노트. **✍️ 표시는 직접 채운다.** 사실 확인용 메모는 이 프로젝트 기준으로 미리 적어 두었다.

## 1. 새로고침해도 남아야 할 데이터는? 백엔드와 DB는 각각 무슨 일을? (sec_1~3)

- 메모: 남아야 할 데이터는 할 일과 태스크, 완료 여부, 마감일. 백엔드(`server.js`)는 요청을 받아 규칙을 검사하고, DB(`todo.db`)는 그 결과를 남긴다.
- ✍️ 내 생각:

## 2. 데이터베이스가 파일 → 관계형 → NoSQL → 클라우드로 발전한 이유 하나 (sec_4)

- ✍️

## 3. 내 Todo 앱의 표·항목·관계는? `SELECT … FROM … WHERE …`를 내 데이터로 (sec_5)

- 메모: 표 2개, todos 1:N tasks. 자세한 건 [database.md](database.md).
- 예: `SELECT title FROM tasks WHERE todo_id = 3 AND completed = 0;` → "3번 할 일의 아직 안 끝난 태스크 제목을 줘"
- ✍️ 내 문장:

## 4. 로그인한 사용자가 자기 할 일만 보게 하려면? (sec_6)

- 메모: Supabase Auth로 로그인, 할 일마다 `user_id` 기록, RLS 정책으로 `user_id = auth.uid()`인 행만 허용. 계정 2개로 시험. [roadmap.md](roadmap.md#rls-정책-초안)
- ✍️

## 5. SQL 주입·비밀번호 유출을 막고, 데이터를 복구하려면 AI에게 무엇을 요구할까? (sec_7)

- 메모: 파라미터화 쿼리 / 비밀번호는 직접 저장하지 말고 검증된 Auth / 비밀값은 `.env` / 백업과 복구 확인. [security.md](security.md), [operations.md](operations.md#백업과-복구)
- ✍️ 내가 쓸 요청 문장:

## 6. 고른 DB의 무료 한도와 백업 정책 (sec_8)

- 메모: SQLite는 내 컴퓨터 파일이라 한도·요금 없음, 백업은 파일 복사. Supabase 무료(강의 기준 2026-02): DB 500MB, 1주 미사용 시 일시정지, 자동 백업 없음. 가입 직전 공식 가격 페이지 재확인.
- ✍️
