# 결정 기록

"왜 이렇게 만들었지?"를 나중에 다시 찾을 수 있게 남기는 기록. 새 결정은 아래에 번호를 이어 붙인다.

형식: **상황** → **결정** → **이유** → **포기한 것**

---

## 001. 길 A의 DB는 SQLite, Node 내장 `node:sqlite`

- **상황**: 강의 길 A는 "내 컴퓨터의 무료 DB". 강의 예시는 `better-sqlite3`인데 Windows에서 빌드 에러가 자주 난다고 안내돼 있다.
- **결정**: Node 24에 내장된 `node:sqlite`를 쓴다.
- **이유**: 설치·빌드할 것이 없다. 다른 사람이 받아도 `npm install` 한 번이면 된다.
- **포기한 것**: 아직 실험 기능이라 실행할 때 경고 문구가 뜬다. Node 24 미만에서는 안 된다.

## 002. 할 일과 태스크를 표 2개로 (todos 1:N tasks)

- **상황**: 할 일 아래 하위 태스크가 필요하다. 태스크는 단독으로 존재할 수 없다.
- **결정**: `todos`, `tasks` 두 표. `tasks.todo_id`는 NOT NULL 외래키, `ON DELETE CASCADE`.
- **이유**: "태스크는 반드시 할 일에 속한다", "한 단계만"이 표 구조 자체로 보장된다. 1:N 관계 연습에도 맞다.
- **포기한 것**: 한 표에 `parent_id`를 두는 방식(여러 단계 중첩 가능)은 쓰지 않았다.

## 003. DB 접근 코드는 `db.js` 한 파일에만

- **상황**: 길 B에서 SQLite → Supabase로 저장소가 바뀐다.
- **결정**: SQL은 `db.js`에만 두고, `server.js`는 함수 이름으로만 부른다.
- **이유**: 저장소를 바꿀 때 고칠 파일이 하나로 줄어든다.

## 004. 규칙은 백엔드에서 다시 검사

- **상황**: 화면에서 막는 규칙(지난 날짜, 완료된 할 일에 태스크 추가 등)은 개발자 도구로 우회할 수 있다.
- **결정**: 모든 규칙을 `server.js`에서 다시 검사하고, 데이터 모양은 DB 제약조건으로도 막는다.
- **이유**: 강의의 "프론트는 못 믿는다" 원칙.

## 005. 안 끝난 태스크가 있는 할 일의 강제 완료 → 남은 태스크도 완료

- **상황**: PRD는 "확인 후 그래도 완료"까지만 정했다.
- **결정**: 확인하면 남은 태스크도 함께 완료 처리. 반대로 태스크를 되돌리면 할 일도 미완료로.
- **이유**: "할 일은 완료인데 태스크는 미완료" 같은 어색한 상태가 생기지 않는다.
- **포기한 것**: "할 일만 완료하고 태스크는 그대로 남기기"는 지원하지 않는다.

## 006. 마감일 필수, 기본값 오늘, 지난 날짜 금지

- **상황**: 사용해 보니 지난 날짜가 실수로 등록됐다.
- **결정**: 할 일 등록 시 마감일 필수, 기본값은 오늘, 지난 날짜는 화면과 백엔드 모두에서 거절.
- **포기한 것**: 마감일 없는 할 일. DB 열은 NULL을 허용한 채로 두었다(이미 저장된 데이터와 호환).

## 007. 중복 제목은 "미완료 할 일끼리"만 금지

- **상황**: 같은 단어를 못 올리게 하고 싶다. 그런데 "장보기"처럼 반복하는 일이 있다.
- **결정**: 미완료 할 일끼리, 같은 할 일 안의 태스크끼리만 금지. 대소문자와 앞뒤 공백은 무시.
- **포기한 것**: DB의 UNIQUE 제약으로 막지 않고 백엔드에서 검사한다. 이미 저장된 데이터에 중복이 있으면 서버가 켜지지 않는 문제를 피하려고. 혼자 쓰는 로컬 앱이라 동시 요청 경쟁은 걱정하지 않았다.

## 008. 완료 90일 후 자동 삭제는 서버 타이머로

- **상황**: 가벼운 DB라 완료 항목을 계속 쌓아 두고 싶지 않다.
- **결정**: `completed_at`을 저장하고, 서버가 켜질 때와 6시간마다 지난 것을 지운다.
- **이유**: 별도 예약 작업 도구 없이 간단하다.
- **포기한 것**: 서버가 꺼져 있는 동안은 지워지지 않는다(켜질 때 한꺼번에 지운다).

## 009. GitHub Pages에는 데모 모드로

- **상황**: Pages는 서버를 실행하지 않는다.
- **결정**: 브라우저 안의 가짜 백엔드(`demo-api.js`)로 같은 규칙을 흉내 내고, 화면에 "데모"라고 밝힌다.
- **이유**: 링크 하나로 화면과 동작을 보여 줄 수 있다.
- **포기한 것**: 데이터가 저장되지 않는다. 규칙을 두 군데(`server.js`, `demo-api.js`)에서 관리해야 한다.

## 010. 문서는 `docs/`에, README는 입구로

- **상황**: README 하나에 DB 표, API, 규칙을 모두 적으니 길어지고, `schema.sql`과 어긋날 위험이 커졌다.
- **결정**: README는 소개·실행·문서 목록만. 자세한 내용은 `docs/`의 주제별 문서로.
