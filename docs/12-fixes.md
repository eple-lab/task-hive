## F-03

**Colab 노트북: ngrok 토큰을 0번 셀에서 먼저 읽는다** · 개선 · 2026-11-18 · eple 제안

- **무엇이**: 처음 Colab 실행(Qwen 측정)에서 6번 ngrok 셀이 두 번 실패했다.
  1. `SecretNotFoundError: Secret NGROK_AUTHTOKEN does not exist` — 보안 비밀 **이름**에 공백이 들어 있었다.
  2. `ERR_NGROK_105` (authtoken 모양이 아니다) — 토큰 **값**이 ngrok이 받는 모양이 아니었다.
- **왜 불편했나**: 토큰은 6번 셀에서야 읽혔다. 그 전에 vLLM 설치·실행(몇 분)이 끝나야 해서 실수를 늦게 알았다. 보안 비밀은 이름·값의 앞뒤 공백이 그대로 남는다.
- **어떻게 고쳤나** (`colab/task_hive_server.ipynb`)
  - 0번 설정 셀이 `NGROK_AUTHTOKEN`(필수)과 `NGROK_DOMAIN`(선택)을 보안 비밀에서 읽는다. 값의 앞뒤 공백·줄바꿈은 지운다.
  - 이름이 없거나 노트북 액세스가 꺼져 있으면 원인을 적은 오류로 바로 멈춘다. `NGROK_DOMAIN`은 없으면 빈 값.
  - 값에 공백이 있거나 `ngrok`으로 시작하면(명령어 `ngrok config add-authtoken …`를 통째로 붙인 경우) 멈춘다.
  - 토큰 값은 찍지 않고 읽었는지(True/False)만 보여 준다.
  - 6번 셀은 `ngrok.set_auth_token(NGROK_AUTHTOKEN)`만 쓴다. 준비 안내를 0번 셀 설명으로 옮겼다.
  - `colab/README.md` 준비 표와 "끊겼을 때" 표에 두 오류와 해결법을 더했다.
- **확인한 것**: 가짜 `google.colab.userdata`로 0번 셀을 5가지 경우로 돌려 기대와 같았다(정상·공백 제거, 도메인 있음, 이름 없음 → 오류, 액세스 꺼짐 → 오류, 명령어 붙임 → 오류). 6번 셀은 문법 검사만 했다.
- **그 뒤**: 같은 Colab 세션에서 8번 셀(PoC-01)은 ngrok 없이 끝까지 돌았다(결과 `eval/results/20261118-011158_qwen4b-colab.*`, 판정 "넘음").
- **Colab에서 확인 (2026-11-18, eple)**: 고친 0번 셀이 "설정 완료. ngrok 토큰 읽음: True / 고정 도메인: 없음"을 출력했다. 이어서 6번 셀이 ngrok 주소를 열었고, 7번 셀이 그 주소로 "상태: 200"과 한국어 인사를 받았다. 게이트웨이 자체 검사도 키 없이 401, 키 넣고 200.
- **확인 못 한 것**: `ERR_NGROK_105`의 실제 원인(값의 공백인지, 다른 값을 복사했는지)은 따로 가리지 않았다. 고친 뒤 통과했으므로 공백이었다면 0번 셀이 지운 것이다(추측).
