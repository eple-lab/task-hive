## T8. 계정 2개 간 RLS 교차 확인
[scripts/rls-check.mjs](../scripts/rls-check.mjs)를 eple이 로컬에서 실행 (서버를 켠 창과 다른 창에서). 비밀번호는 `.env`에만 있고 문서에는 적지 않는다.

### 1차 (원래 스크립트, 15개): 15/15 통과
A가 할 일 #4와 태스크 #3을 만들고, B로 서버 API와 Supabase 직접 호출 양쪽에서 보기·검색·완료·태스크 추가·삭제를 시도했다. 모두 거절되거나 0행이었고, A의 데이터는 그대로였다.

**검토에서 찾은 약점**: B의 목록이 처음부터 비어 있었다(B 할 일 0개). "A의 것을 못 본다"와 "B가 아무것도 못 본다(고장)"를 구분할 B 쪽 대조군이 없었고, 반대 방향(A가 B의 것을 못 보는지)도 확인하지 않았다.

### 2차 (보강, 19개): 18/19
B도 자기 할 일을 만들고 4개 검사를 추가했다.

| 추가한 검사 | 결과 |
|---|---|
| [서버] B의 목록에 B의 할 일은 있다 (대조군) | PASS (B의 목록 1개) |
| [서버] A의 목록에 B의 할 일이 없다 (반대 방향) | PASS |
| [직접] B가 자기 할 일 조회 → 1행 (대조군) | PASS |
| [직접] A가 B의 할 일 조회 → 0행 (반대 방향) | PASS |

FAIL 1건: `[서버] B가 A의 제목으로 검색해도 안 나온다 (1건)`.
B의 대조군 제목에 A의 제목 문자열이 들어 있어서 B 자신의 할 일이 검색된 **테스트 버그**다. 같은 실행에서 "B의 목록에 A의 할 일이 없다", "[직접] B가 A의 할 일 조회 → 0행"이 PASS라 RLS 누출은 아니다. 자세한 원인·수정은 [BUG-002](bugfix.md#bug-002).

### 3차 (BUG-002 수정본, 19개): 19/19 통과
A가 할 일 #7·태스크 #7, B가 대조군 할 일 #8을 만들고 실행. 끝난 뒤 #7, #8 모두 삭제.

| 비로그인 직접 조회 | `permission denied for table todos` |
| A의 데이터 | 제목·완료 상태·태스크 1개 그대로 |

**결론**: "각 사용자는 자기 할 일만 보고 다룬다"가 서버 API와 Supabase 직접 호출 양쪽, 양방향에서 확인됐다.
