# PoC (직접 실행해 확인할 것)

문서와 검색으로는 알 수 없어 **직접 실행해야 확인되는 것**을 실험 하나에 문서 하나로 정리한다. 지금은 기본 구조만 있고 결과 칸은 비어 있다.

| 번호 | 실험 | 답하려는 질문 | 필요한 단계 | 상태 |
|---|---|---|---|---|
| [PoC-01](poc-01-llm-summary.md) | LLM 요약·할 일 추출 | Colab의 작은 LLM이 한국어 대화를 요약하고 할 일을 뽑을 수 있는가 | 1단계 전 | 시작 전 |

PoC-01이 과제의 중심이다. 메인 퀘스트의 "AI 모델을 직접 실행해 내 도메인 데이터에 적용"과 "개선 효과 검증"이 여기서 나온다.

## 공통 규칙

수업 「내 업무 어디에 AI를 넣을까?」의 원칙을 따른다.

1. **성공 기준을 먼저 적는다.** 만들기 전에 숫자로 적는다. 숫자의 근거는 지금 사람이 하는 수준이다.
2. **정답을 먼저 적는다.** 모델을 돌리기 전에 기대 결과를 적는다. 결과를 보고 정하지 않는다.
3. **지금 방식(기준선)을 후보에 넣는다.** 기준선이 이기면 그것도 결과다.
4. **통과/탈락 조건을 먼저 본다.** 실행 위치와 라이선스는 감점이 아니라 탈락 조건이다.
5. **성격이 다른 후보를 고른다.** 같은 모델의 크기만 바꾸지 않는다.
6. **자료는 10~20건, 그중 3~4건은 어려운 것.**
7. **숫자를 반올림하지 않는다. 결과 파일을 덮어쓰지 않는다.**
8. **눈으로 확인할 수 있는 형태로 함께 남긴다.** (원문과 결과를 나란히)
9. **못 넘으면 "못 넘음"과 이유를 그대로 적는다.** 못 넘은 이유도 결과다.
10. **확인한 날짜와 링크를 적는다.**

## 개인정보 규칙

- 실험 자료는 **가상 대화**만 쓴다. 실제 일기, 실제 캘린더 일정, 다른 사람의 이름을 쓰지 않는다.
- 캘린더·드라이브 실험은 eple 본인의 테스트 계정으로만 한다.
- 노트북을 저장소에 올리기 전에 출력(ngrok 주소, 접속 키, 토큰)을 지운다.
- 목소리 복제 실험에 남의 목소리를 쓰지 않는다.

## 문서 구조

모든 실험 문서는 같은 순서를 따른다. 새 실험은 [_template.md](_template.md)를 복사해 만든다.

| 절 | 언제 채우나 |
|---|---|
| 1. 질문 | 실험 전 |
| 2. 왜 필요한가 | 실험 전 |
| 3. 성공 기준 | 실험 전 |
| 4. 후보와 통과/탈락 조건 | 실험 전 |
| 5. 자료와 정답 | 실험 전 (정답은 돌리기 전에) |
| 6. 절차 | 실험 전 |
| 7. 결과 | 실험 뒤 |
| 8. 실패 사례 | 실험 뒤 |
| 9. 판정과 다음 단계 | 실험 뒤 |
| 10. 실행 기록 | 실험 뒤 (날짜, 환경, 버전) |
