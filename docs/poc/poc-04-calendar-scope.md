# PoC-04. 캘린더 권한 분류

상태: 시작 전 · 관련: [D-14](../02-decisions.md), [checks/google-oauth-7day-expiry.md](../checks/google-oauth-7day-expiry.md)

## 1. 질문

`calendar.events.owned.readonly`(내가 소유한 캘린더의 일정 보기)는 구글 분류에서 민감한 권한인가? 이 권한만으로 필요한 일정을 읽을 수 있는가?

## 2. 왜 필요한가

- 민감한 권한이면 앱을 게시할 때 구글 심사가 필요하고, 심사 전에는 "확인되지 않은 앱" 경고와 사용자 100명 한도가 있다.
- 공식 문서에는 캘린더 권한별 분류 표시가 없다. Google Cloud Console 화면에서만 볼 수 있다.
- 이 실험은 코드가 아니라 **eple의 콘솔 화면 확인**이다.

## 3. 성공 기준 (실험 전에 적는다)

| 기준 | 내용 |
|---|---|
| 분류 확인 | 콘솔에 표시된 분류(민감하지 않음 / 민감 / 제한)를 적는다 |
| 읽기 범위 | 이 권한으로 내 기본 캘린더의 지난 7일 + 앞으로 30일 일정을 읽을 수 있다 |
| 읽지 않는 것 | 공유받은 남의 캘린더 일정은 읽히지 않는다 |
| 동의 화면 문구 | 사용자에게 보이는 문구를 적는다 (화면 안내에 그대로 쓴다) |

## 4. 후보와 통과/탈락 조건

| 권한 | 뜻 | 메모 |
|---|---|---|
| `calendar.events.owned.readonly` | 내가 소유한 캘린더의 일정 보기 | **확정** (D-14) |
| `calendar.events.readonly` | 볼 수 있는 모든 캘린더의 일정 보기 | 비교용. 쓰지 않는다 |
| `calendar.readonly` | 캘린더 전체 보기와 내려받기 | 비교용. 쓰지 않는다 |

## 5. 자료와 정답

- eple의 테스트용 구글 계정. 가상 일정 몇 개를 미리 만든다(실제 일정이 화면 캡처에 찍히지 않게).
- 미리 적어 둘 예상: "민감한 권한으로 표시될 것이다"(구글이 캘린더 일정 읽기를 민감한 권한의 예로 든다).

## 6. 절차

1. Google Cloud Console에서 프로젝트를 만들고 Google Calendar API를 사용 설정한다.
2. OAuth 동의 화면의 권한 추가 화면에서 위 세 권한을 찾아 분류 표시를 적는다.
3. `calendar.events.owned.readonly`만 추가한다.
4. 테스트 사용자로 본인 계정을 등록한다.
5. 동의 화면을 띄워 사용자에게 보이는 문구를 적는다.
6. 일정 읽기를 호출해 기본 캘린더, 내가 만든 보조 캘린더, 공유받은 캘린더, 생일·공휴일 캘린더의 일정이 각각 읽히는지 적는다.
7. 화면 캡처를 남길 때는 계정 이메일과 실제 일정이 보이지 않게 한다.
