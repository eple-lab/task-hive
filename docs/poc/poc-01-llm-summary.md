# PoC-01. LLM 요약·할 일 추출

상태: 시작 전 · 관련: [D-13](../02-decisions.md), [Q-13, Q-19, Q-20](../07-open-questions.md), [08 성능 검토 화면](../08-performance-review.md) 5장

## 1. 질문

Colab에 올린 작은 LLM이 한국어 저녁 대화를 **요약**하고, 그 안에서 **할 일을 뽑을** 수 있는가?

## 2. 왜 필요한가

- Task Hive의 핵심 기능(대화 → 할 일 후보, 대화 → 일기 요약)이 여기에 달려 있다.
- 과제의 "AI 모델 직접 실행", "개선 효과 검증", "실패 사례"가 이 실험에서 나온다.
- 업무 유형으로는 "입력과 전사"(말한 것을 할 일로 옮겨 적기)에 가깝다. 이 유형은 효과가 직접적이지만 **틀려도 그럴듯해 보여 알아채기 어렵다.** 그래서 근거 문장을 함께 보여 주는지도 본다.

## 3. 성공 기준 (실험 전에 적는다)

숫자는 예시다. eple이 정한다([Q-20](../07-open-questions.md)). 기존 방식을 먼저 재서 근거를 채운다.

| 기준 | 숫자 (예시, 미확정) | 근거 |
|---|---|---|
| 할 일 추출: 놓치지 않은 비율 | 대화 20건의 할 일 중 85% 이상 | 미정 (사람이 직접 적을 때 놓치는 비율을 먼저 잰다) |
| 할 일 추출: 지어낸 할 일 | 20건 전체에서 2개 이하 | 지어낸 할 일은 사용자가 지워야 해서 불편하다 |
| 할 일이 없는 대화 | 3건 모두 후보를 내지 않는다 | "없다"고 답할 수 있어야 한다 |
| 날짜 | 날짜 표현이 있는 할 일의 80% 이상에서 맞는 날짜 | 미정 |
| 완료 신호 | "그건 한 것 같아"류 10건 중 8건에서 맞는 태스크 | R-CHAT-9 |
| 요약 | 20건 중 18건에서 대화에 없는 내용이 없고, 핵심 사건이 빠지지 않는다 | 사람이 읽고 판정 |
| 근거 표시 | 모든 후보에 근거가 된 대화 문장이 붙는다 | 오류 자리를 원문에서 찾을 수 있어야 한다 |
| 속도 | 첫 글자까지 3초 이하 (중앙값) | 비기능 요구사항 |
| 등록 시간 | 같은 할 일을 `todo` 앱에 직접 넣을 때보다 짧다 | 기준선 |

## 4. 후보와 통과/탈락 조건

통과/탈락 조건:

- 실행 위치: 본인 Colab(또는 본인 PC)에서 돈다. 대화를 외부 AI 회사 API로 보내지 않는다.
- 라이선스: 과제·데모 용도를 허용한다. 설치한 패키지의 배포 정보로 확인한다.
- 한국어: 한국어 입력과 출력이 된다.
- 구조화 출력: 정해진 JSON 형식으로 답할 수 있다.
- 메모리: Colab 무료 GPU에 올라간다 ([PoC-03](poc-03-colab-gpu-memory.md)).

| 후보 | 성격 | 통과/탈락 | 메모 |
|---|---|---|---|
| 기준선: `todo` 앱에 직접 입력 | 사람이 떠올려 적는다 | - | 시간, 누른 횟수, 놓친 할 일을 잰다 |
| Qwen 4B급 AWQ (`llm-chatbot`에서 쓴 것) | 범용 소형, Colab | 미확인 | thinking을 꺼야 바로 답한다 |
| (후보 2) | 한국어 특화 또는 더 큰 양자화 모델 | 미확인 | eple이 정한다 |
| (후보 3) | 성격이 다른 후보 (예: 로컬 PC의 Ollama) | 미확인 | 실행 위치가 다르다 |

## 5. 자료와 정답

- 자료: **가상 저녁 대화 20건** (`eval/samples/`). 실제 일기는 쓰지 않는다.
- 어려운 것 4건 이상을 넣는다.

| 종류 | 예 | 건수 (안) |
|---|---|---|
| 평범한 대화, 할 일 1~3개 | "내일 병원 예약해야 해" | 10 |
| 할 일이 없는 대화 | 하루 이야기만 | 3 |
| 부정·취소 | "그건 안 해도 될 것 같아" | 2 |
| 남의 일 | "동생이 이사 준비한대" | 2 |
| 애매한 날짜 | "다음 주쯤", "월말까지" | 2 |
| 하위 태스크가 있는 일 | "여행 준비: 숙소, 기차표, 짐" | 1 |

- 완료 신호용 자료 10건: 등록된 태스크 목록 + "그건 한 것 같아"류 발화.
- 정답: 대화마다 기대하는 할 일(제목, 날짜, 하위 태스크), 기대하는 요약의 핵심 사건을 **모델을 돌리기 전에** 적는다.

## 6. 절차

1. 가상 대화와 정답을 쓴다.
2. 기준선을 잰다: 같은 대화를 읽고 `todo` 앱에 직접 넣는 시간과 놓친 할 일.
3. 후보를 통과/탈락 조건으로 거른다.
4. Colab에서 모델을 띄우고 같은 지시문, 같은 JSON 형식으로 20건을 돌린다.
5. 결과를 정답과 비교한다. 원문, 정답, 결과를 나란히 저장한다.
6. 틀린 것을 종류별로 묶는다.
7. 지시문을 고쳐 다시 돌릴 때는 결과 파일을 새 이름으로 남긴다.
