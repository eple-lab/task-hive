# PoC-01. LLM 요약·할 일 추출

상태: 진행 중 (llama3.2 측정 끝, Qwen 4B·기준선 남음, 2026-11-17) · 관련: [D-13](../02-decisions.md), [Q-13, Q-19, Q-20](../07-open-questions.md), [08 성능 검토 화면](../08-performance-review.md) 5장

## 1. 질문

Colab에 올린 작은 LLM이 한국어 저녁 대화를 **요약**하고, 그 안에서 **할 일을 뽑을** 수 있는가?

## 2. 왜 필요한가

- Task Hive의 핵심 기능(대화 → 할 일 후보, 대화 → 일기 요약)이 여기에 달려 있다.
- 과제의 "AI 모델 직접 실행", "개선 효과 검증", "실패 사례"가 이 실험에서 나온다.
- 업무 유형으로는 "입력과 전사"(말한 것을 할 일로 옮겨 적기)에 가깝다. 이 유형은 효과가 직접적이지만 **틀려도 그럴듯해 보여 알아채기 어렵다.** 그래서 근거 문장을 함께 보여 주는지도 본다.

## 3. 성공 기준 (실험 전에 적는다)

판정 기준은 eple이 정했다([D-33](../02-decisions.md), "보통" 수준). `eval/run_eval.py`가 이 세 숫자로 판정한다. 모델을 돌리기 전인 2026-11-17에 정답과 함께 고정했다.

| 판정 기준 | 숫자 | 근거 |
|---|---|---|
| 할 일을 놓치지 않은 비율(재현율) | 20건의 할 일 19개 중 **80% 이상** | 핵심 기능. 놓치면 사용자가 다시 적어야 한다 |
| 지어낸 할 일 | 20건 전체에서 **3개 이하** | 지어낸 할 일은 사용자가 지워야 해서 불편하다 |
| 할 일이 없는 대화 | 3건 중 **2건 이상**에서 아무것도 뽑지 않는다 | "없다"고 답할 수 있어야 한다 |
| 등록 시간 | 같은 할 일을 `todo` 앱에 손으로 넣을 때보다 **짧다** | 기준선(eple이 직접 잰다) |

판정에 넣지 않고 함께 보는 지표: 날짜 정확도, 완료 신호("그건 한 것 같아") 정확도, 하위 태스크, 근거 문장이 붙은 비율, JSON 형식 오류, 첫 글자까지 시간. 처음 초안에 있던 예시 숫자(85%, 2개 이하, 3건 모두 등)는 D-33으로 대체했다.

## 4. 후보와 통과/탈락 조건

통과/탈락 조건:

- 실행 위치: 본인 Colab(또는 본인 PC)에서 돈다. 대화를 외부 AI 회사 API로 보내지 않는다.
- 라이선스: 과제·데모 용도를 허용한다. 설치한 패키지의 배포 정보로 확인한다.
- 한국어: 한국어 입력과 출력이 된다.
- 구조화 출력: 정해진 JSON 형식으로 답할 수 있다.
- 메모리: Colab 무료 GPU에 올라간다 ([PoC-03](poc-03-colab-gpu-memory.md)).

| 후보 | 성격 | 통과/탈락 | 메모 |
|---|---|---|---|
| 기준선: `todo` 앱에 직접 입력 | 사람이 떠올려 적는다 | - | 시간, 누른 횟수, 놓친 할 일을 잰다 |
| Qwen 4B급 AWQ (`llm-chatbot`에서 쓴 것) | 범용 소형, Colab | 미확인 | thinking을 꺼야 바로 답한다 |
| (후보 2) | 한국어 특화 또는 더 큰 양자화 모델 | 미확인 | eple이 정한다 |
| llama3.2 (3B, Ollama, 로컬 PC) | 성격이 다른 후보. 실행 위치가 본인 PC(CPU) | 통과 (조건 5개 모두. 구조화 출력은 JSON 형식 오류 0건으로 확인) | [D-34](../02-decisions.md) |

## 5. 자료와 정답

- 자료: **가상 저녁 대화 20건** (`eval/samples/`). 실제 일기는 쓰지 않는다.
- 어려운 것 4건 이상을 넣는다.

| 종류 | 예 | 건수 (안) |
|---|---|---|
| 평범한 대화, 할 일 1~3개 | "내일 병원 예약해야 해" | 10 |
| 할 일이 없는 대화 | 하루 이야기만 | 3 |
| 부정·취소 | "그건 안 해도 될 것 같아" | 2 |
| 남의 일 | "동생이 이사 준비한대" | 2 |
| 애매한 날짜 | "다음 주쯤", "월말까지" | 2 |
| 하위 태스크가 있는 일 | "여행 준비: 숙소, 기차표, 짐" | 1 |

- 완료 신호용 자료 10건: 등록된 태스크 목록 + "그건 한 것 같아"류 발화.
- 정답: 대화마다 기대하는 할 일(제목, 날짜, 하위 태스크), 기대하는 요약의 핵심 사건을 **모델을 돌리기 전에** 적는다.

## 6. 절차

1. 가상 대화와 정답을 쓴다.
2. 기준선을 잰다: 같은 대화를 읽고 `todo` 앱에 직접 넣는 시간과 놓친 할 일.
3. 후보를 통과/탈락 조건으로 거른다.
4. Colab에서 모델을 띄우고 같은 지시문, 같은 JSON 형식으로 20건을 돌린다.
5. 결과를 정답과 비교한다. 원문, 정답, 결과를 나란히 저장한다.
6. 틀린 것을 종류별로 묶는다.
7. 지시문을 고쳐 다시 돌릴 때는 결과 파일을 새 이름으로 남긴다.

## 9. 판정과 다음 단계

- 판정 (llama3.2): **못 넘음.** 판정 기준 세 개(재현율 0.63 < 0.8, 지어냄 8 > 3, 없는 대화 0/3 < 2/3)를 모두 넘지 못했다. 등록 시간은 기준선이 아직 없어 판정하지 못했다.
- 못 넘은 이유 (추측): 3B급 작은 모델은 대화에서 "할 일처럼 보이는 문장"을 찾는 것은 어느 정도 하지만, **할 일이 아닌 것(지난 일, 취소, 남의 일)을 거르는 것**을 거의 하지 못했다. 지어낸 8개 중 7개가 거르기 문제(①②③)에서 나왔다. 반면 애매한 날짜와 하위 태스크 구조는 맞혔다.
- 서비스에 주는 뜻: 후보를 "사용자가 담아야 등록"하게 한 설계(D-21, 계약의 candidates)는 이 결과에서 필요성이 확인됐다. 모델이 지어낸 후보는 사용자가 "빼기"로 버릴 수 있다. 다만 지어낸 후보가 많으면 손 입력보다 느려질 수 있어 기준선 비교가 필요하다.
- 반영할 문서: [02](../02-decisions.md) 모델 결정(Qwen 결과 뒤에), [08](../08-performance-review.md) 검증 탭, 과제 문제 정의서
- 다음에 바꿔서 다시 확인할 것:
  1. Qwen 4B AWQ(Colab GPU)로 같은 20건 — 더 큰 모델이 거르기를 하는지.
  2. 지시문의 예시 문구 복사(⑤) — 예시를 대화와 겹치지 않는 형식(예: 자리표시자)으로 바꿔 다시 잰다. 지시문을 바꾸면 결과 파일을 새 이름으로 남긴다(6장 7번).
  3. 근거 문장이 실제로 그 할 일을 말하는지 재는 지표.
  4. 기준선(손 입력 시간·놓친 수)과 비교.
