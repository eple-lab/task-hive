# PoC-05. Docs 이미지 넣기

상태: 시작 전 · 관련: R-DIARY-5, [Q-08](../07-open-questions.md), [checks/docs-image-insert.md](../checks/docs-image-insert.md)

## 1. 질문

사용자의 드라이브 「테스크 하이브 일기/이미지」 폴더에 올린 사진을, **사진을 공개하지 않고** 구글 Docs 일기 안에 넣을 수 있는가?

## 2. 왜 필요한가

- Docs API의 이미지 삽입은 공개 주소를 요구한다(확인함). 비공개 드라이브 파일은 거절된다는 외부 기록이 있다.
- 공개하지 않고 넣는 방법이 있는지에 따라 "Docs 일기에 이미지" 기능의 모양이 정해진다.

## 3. 성공 기준 (실험 전에 적는다)

| 기준 | 내용 |
|---|---|
| 비공개 유지 | 실험 전후로 사진 파일의 공유 설정이 "제한됨"이다. 한순간도 공개되지 않는다 |
| 그림 표시 | Docs 문서를 열면 사진이 그림으로 보인다 |
| 권한 | `drive.file` 권한만으로 된다 |
| 남는가 | 넣은 뒤 원본 사진을 지워도 문서의 그림이 남는다 |

네 가지를 모두 만족하는 방법이 있으면 성공이다. 없으면 "링크만 넣기"로 간다.

## 4. 후보와 통과/탈락 조건

탈락 조건: 사진이 잠깐이라도 공개되는 방법은 결과가 좋아도 쓰지 않는다.

| 방법 | 설명 | 미리 적은 예상 |
|---|---|---|
| A. 링크만 넣기 (기준선) | 사진은 이미지 폴더에, Docs에는 링크 | 된다. 그림은 안 보인다 |
| B. 잠깐 공유했다가 되돌리기 | "링크가 있는 누구나" → 삽입 → 비공개 | 될 것이다. **탈락 조건에 걸린다.** 넣은 뒤에도 그림이 남는지만 확인한다 |
| C. `.docx`로 만들어 올리며 변환 | 서버에서 사진을 넣은 Word 파일을 만들어 Docs로 변환 | 그림이 남을 것 같다. 기존 문서에 덧붙일 수는 없다 |
| D. 드라이브 주소를 그대로 넣기 | 비공개 파일의 내려받기 주소, 썸네일 주소 | 실패할 것이다 (외부 기록과 같은지 확인) |
| E. Apps Script | 사용자 권한으로 파일을 읽어 넣기 | 될 것이다. 구조가 복잡해 쓰지 않을 가능성이 높다. 시간이 남으면 확인 |

## 5. 자료와 정답

- 시험 사진 3장: 작은 PNG, 휴대폰 크기 JPEG, 큰 JPEG(10MB 안팎). 사람이 찍히지 않은 사진을 쓴다.
- eple의 테스트용 구글 계정.

## 6. 절차

1. `drive.file` 권한으로 「테스크 하이브 일기」 폴더와 「이미지」 하위 폴더를 만든다.
2. 시험 사진을 이미지 폴더에 올린다.
3. 방법 A, D, C, B 순서로 시도한다. 방법마다 요청과 응답(오류 코드)을 적는다.
4. 방법마다 사진 파일의 공유 설정을 전후로 확인한다.
5. 그림이 들어갔다면 원본 사진을 지우고 문서를 다시 열어 그림이 남는지 본다.
6. 사용자가 드라이브 화면에서 직접 올린 사진을 앱이 읽을 수 있는지도 확인한다.
7. 시트의 `IMAGE()` 함수로도 같은 사진이 보이는지 확인한다.
