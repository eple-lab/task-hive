# PoC-03. Colab GPU 메모리

상태: 시작 전 · 관련: [D-10](../02-decisions.md), [checks/colab-usage.md](../checks/colab-usage.md)

## 1. 질문

Colab 무료 GPU 하나에 대화 모델(LLM) + TTS + Whisper가 **함께** 올라가고, 대화하는 동안 메모리가 부족하지 않은가?

## 2. 왜 필요한가

- 2단계의 "말로 입력 → 대화 → 말로 답"은 세 모델이 같은 Colab에서 돌아야 한다.
- 안 올라가면 모델을 줄이거나, TTS·Whisper를 CPU로 돌리거나, 2단계 범위를 바꿔야 한다.
- Colab은 GPU 종류를 보장하지 않는다. 받은 GPU에 따라 결과가 달라진다.

## 3. 성공 기준 (실험 전에 적는다)

| 기준 | 숫자 (예시, 미확정) | 근거 |
|---|---|---|
| 함께 올라감 | 세 모델을 올린 뒤 GPU 메모리 여유 10% 이상 | 대화가 길어지면 더 쓴다 |
| 긴 대화 | 20번 주고받은 뒤에도 메모리 부족 오류가 없다 | 저녁 대화 한 번의 길이 |
| 속도 | 세 모델을 함께 올려도 첫 글자까지 3초 이하 | 비기능 요구사항 |
| 다시 켜기 | 노트북을 처음부터 실행해 연결 가능해지기까지의 시간을 안다 | README에 적을 값 |

## 4. 후보와 통과/탈락 조건

| 구성 | 설명 |
|---|---|
| A. LLM만 | 1단계 최소 구성 |
| B. LLM + TTS | 1단계 목표 구성 |
| C. LLM + TTS + Whisper (GPU) | 2단계 목표 구성 |
| D. LLM(GPU) + TTS·Whisper(CPU) | C가 안 될 때의 대안 |

조정할 수 있는 값: vLLM이 미리 잡는 GPU 메모리 비율, 최대 문맥 길이, Whisper 모델 크기.

## 5. 자료와 정답

- [PoC-01](poc-01-llm-summary.md)의 가상 대화를 그대로 쓴다.
- 미리 적어 둘 예상: 구성별로 "올라갈 것 같다 / 안 올라갈 것 같다"와 이유.

## 6. 절차

1. 노트북을 새로 열고 받은 GPU 종류와 전체 메모리를 적는다.
2. 구성 A → B → C 순서로 모델을 하나씩 올리며, 올린 직후 GPU 메모리 사용량을 적는다.
3. 구성마다 가상 대화로 20번 주고받고 최대 사용량, 첫 글자 시간, 초당 토큰을 적는다.
4. C가 안 되면 조정값을 바꾸거나 D로 다시 잰다.
5. 날을 바꿔 한 번 더 한다. 다른 GPU를 받으면 그 결과도 적는다.
