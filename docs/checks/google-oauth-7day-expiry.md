# 구글 로그인 7일 만료

확인한 날: 2026-11-17

## 0. 결정 (2026-11-17)

eple이 **방법 B(1시간짜리 토큰만, refresh token을 받지 않음)**로 정했다([D-19](../02-decisions.md)). 그래서 7일 만료 규칙은 Task Hive에 직접 닿지 않는다. 대신 약 1시간이 지나면 구글 기능을 쓸 때 "구글 다시 연결"을 눌러야 한다. 아래 내용은 이 결정의 근거와, 나중에 refresh token을 쓰게 될 때를 위한 기록이다.

## 1. 한 줄 결론 (refresh token을 쓸 경우)

Task Hive의 구글 앱이 "테스트" 상태인 동안, **구글 기능(캘린더, 일기 저장, 태스크 시트)을 하나라도 켠 사용자는 7일마다 구글 연결을 다시 해야 한다.** 구글 로그인만 하고 기능을 모두 꺼 둔 사용자는 해당하지 않는다.

## 2. 규칙 (확인함)

구글 공식 문서의 내용이다.

| 규칙 | 내용 |
|---|---|
| 대상 | OAuth 동의 화면의 사용자 유형이 "외부"이고 게시 상태가 "테스트"인 프로젝트 |
| 결과 | refresh token이 발급 7일 뒤 만료된다 |
| 예외 | 요청한 권한이 이름·이메일·프로필(`openid`, `userinfo.email`, `userinfo.profile`)뿐일 때 |
| 테스트 사용자 | 동의 화면에 등록한 계정만 쓸 수 있다. 최대 100명 |
| 테스트 사용자 예외 | 기본 신원 권한(`openid`, `email`, `profile`)만 요청하는 앱은 등록하지 않은 사용자도 쓸 수 있다 |
| 토큰 개수 | 구글 계정 하나가 클라이언트 하나에서 받을 수 있는 refresh token은 100개. 넘으면 가장 오래된 것이 예고 없이 무효가 된다 |

refresh token이 7일 규칙과 상관없이 무효가 되는 다른 경우(확인함):

- 사용자가 구글 계정 설정에서 앱 접근을 해제했다.
- 6개월 동안 쓰지 않았다.
- 사용자가 기간을 정해 허락했고 그 기간이 끝났다.
- 계정의 refresh token 개수 한도를 넘었다.

출처: [Using OAuth 2.0 to Access Google APIs](https://developers.google.com/identity/protocols/oauth2), [OAuth app state overview](https://developers.google.com/identity/protocols/oauth2/production-readiness/overview)

## 3. 용어

| 용어 | 뜻 |
|---|---|
| access token | 구글 API를 부를 때 쓰는 짧은 수명의 열쇠. 구글 문서는 "수명이 제한된다"고만 적는다. `honey-voice-log`에서는 약 1시간이었다 |
| refresh token | access token이 만료되면 사용자에게 다시 묻지 않고 새로 받는 데 쓰는 긴 수명의 열쇠. 오프라인 접근을 요청해야 받는다 |
| 테스트 상태 | 구글의 심사를 받지 않고 등록한 테스트 사용자만 쓰는 상태 |
| 게시(프로덕션) 상태 | 누구나 쓸 수 있는 상태. 민감한 권한을 쓰면 심사가 필요하다 |

## 4. Task Hive에는 어떻게 적용되나

Task Hive가 요청하는 권한과 7일 규칙의 관계다.

| 사용자가 켠 기능 | 요청하는 권한 | 7일 만료 | 테스트 사용자 등록 |
|---|---|---|---|
| 구글 로그인만 (캘린더·일기·태스크 시트 모두 끔) | `openid` | **해당 없음** (예외) | 필요 없음 |
| 일기를 구글 시트·Docs에 저장, 또는 태스크 시트 | `openid` + `drive.file` | **해당** | 필요 |
| 캘린더 가져오기 | `openid` + `calendar.events.owned.readonly` | **해당** | 필요 |
| 모두 켬 | 위 전부 | **해당** | 필요 |

짚어 둘 점:

- `drive.file`은 구글 분류상 **민감하지 않은 권한**이지만 7일 규칙의 예외는 아니다. 예외는 이름·이메일·프로필 권한뿐이다.
- 그래서 **기능을 켜고 끌 수 있게 한 결정**(D-14, D-15)이 여기서 도움이 된다. 구글 기능을 켜지 않은 사용자는 7일 만료도, 테스트 사용자 등록도 필요 없다.
- 기능을 켤 때 그 권한을 추가로 요청한다(단계적 권한 요청). 처음 로그인할 때는 `openid`만 요청한다.

### 사용자가 겪는 모습

1. 첫날: 구글 로그인 → 일기 저장을 켬 → 구글 동의 화면에서 드라이브 권한 허락.
2. 1~7일: 다시 묻지 않고 일기가 저장된다.
3. 8일째: 일기 저장을 누르면 구글이 토큰을 거절한다. Task Hive는 "구글 연결이 끊겼어요. 다시 연결할까요?"를 보여 준다.
4. 다시 연결하면 또 7일 동안 쓴다.

대화, 벌집, 태스크 체크는 구글 연결과 상관없이 계속 된다. 끊기는 것은 캘린더 읽기와 드라이브 쓰기뿐이다.

## 5. 대응 방법 비교

| 방법 | 설명 | 장점 | 단점 |
|---|---|---|---|
| A. 테스트 상태 유지, refresh token 저장 | 지금 계획. 토큰을 암호화해 Neon에 둔다 | 7일 동안은 다시 묻지 않는다. 심사가 없다 | 7일마다 재연결. 서버에 오래 가는 토큰이 있다 |
| B. 테스트 상태 유지, refresh token을 받지 않음 | `honey-voice-log` 방식. access token만 쓰고 만료되면 다시 연결 | 서버에 오래 가는 토큰이 없다. 7일 규칙을 신경 쓸 일이 없다 | 약 1시간마다 재연결. 저녁에 한 번 쓰는 서비스라면 감수할 만하다 |
| C. 게시(프로덕션) 상태로 전환, 심사 없이 | 누구나 쓸 수 있고 7일 규칙이 사라진다 | 재연결이 없다 | 민감한 권한(캘린더로 추정)을 쓰면 "확인되지 않은 앱" 경고가 뜨고 사용자 100명 한도가 있다. 구글은 이 방식을 권하지 않는다 |
| D. 게시 + 구글 심사 통과 | 정식 서비스 방식 | 경고도 한도도 없다 | 개인정보처리방침, 도메인 소유 확인, 심사 기간이 필요하다 |
| E. 구글 Workspace 내부 앱 | 사용자 유형 "내부" | 7일 규칙과 한도가 없다 | Workspace 조직 계정에서만 된다. 개인 gmail 계정은 못 쓴다 |

출처 메모: C의 "100명 한도"와 "권하지 않는다"는 구글의 [OAuth app state overview](https://developers.google.com/identity/protocols/oauth2/production-readiness/overview)에서 확인했다. 캘린더 권한이 민감한 권한인지는 공식 문서에 표시가 없어 [PoC-04](../poc/poc-04-calendar-scope.md)에서 콘솔로 확인한다. 민감하지 않은 권한만 쓰는 앱을 게시했을 때의 조건은 확인한 문서에 없었다.

## 6. 추천

| 시기 | 추천 | 이유 |
|---|---|---|
| 과제 기간 (지금) | **A 또는 B** 중 eple이 선택 | 심사 없이 바로 쓸 수 있다. 시연은 7일 안에 끝난다 |
| 데모를 다른 사람에게 열 때 | 그대로 두고 테스트 사용자로 등록 | 100명까지 가능 |
| 실제 서비스로 갈 때 | D | 그때 개인정보처리방침과 도메인이 필요하다 |

**eple의 선택은 B다(D-19).** Claude의 추천은 A였다. 구글 화면으로 다녀오는 일이 잦아지는 점 때문이었는데, eple은 서버에 오래 가는 토큰을 두지 않는 쪽을 골랐다.

B에서 사용자가 겪는 모습: 저녁에 들어와 구글 기능을 연결하면 약 1시간 동안 일기 저장, 캘린더 읽기, 시트 내보내기가 된다. 1시간이 지난 뒤 다시 쓰려면 "구글 다시 연결"을 한 번 누른다. 그때 동의 화면이 얼마나 짧게 지나가는지는 실행해 확인한다.

## 7. 설계에 반영할 것

| 항목 | 내용 |
|---|---|
| 처음 로그인 | `openid`만 요청한다 |
| 기능을 켤 때 | 그 기능의 권한만 추가로 요청한다 |
| 기능을 끌 때 | 그 기능을 더 쓰지 않는다. 권한 해제는 "구글 연결 해제" 버튼으로 따로 한다 |
| 토큰이 거절될 때 | `invalid_grant` 오류를 "연결이 끊겼어요" 안내로 바꾼다. 오류 내용을 그대로 보여 주지 않는다 |
| 만료 알리기 | 토큰 만료 시각을 알고 있으므로, 만료되면 상태창의 구글 연결 상태를 "끊김"으로 바꾸고 "구글 다시 연결" 버튼을 보여 준다 |
| 오프라인 접근 | 요청하지 않는다. refresh token이 오지 않는다 |
| 끊겨도 되는 것 | 대화, 벌집, 체크, MD 내려받기 |
| 끊기면 안 되는 것 | 없음. 일기 요약은 화면에 남아 있어 다시 연결한 뒤 저장할 수 있다 |
| 테스트 | 만료된 토큰을 흉내 낸 가짜 구글 응답으로 안내 화면이 뜨는지 확인한다 |
| 성능 화면 | "구글 연결 끊김" 횟수를 지표로 센다 |
