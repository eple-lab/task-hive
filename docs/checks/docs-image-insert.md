# Docs에 이미지 넣기

확인한 날: 2026-11-17

## 1. 질문

사용자의 구글 드라이브 일기 폴더 아래에 이미지 폴더를 만들고, 거기에 올린 사진을 구글 Docs 일기에 넣을 수 있는가?

## 2. 한 줄 결론

**이미지 폴더에 사진을 올리는 것은 된다. 그 사진을 Docs 문서 안에 "그림으로" 넣는 것은 폴더에 두는 것만으로는 안 된다.** Docs API가 사진을 가져올 때 로그인 없이 가져가기 때문에, 비공개 드라이브 파일의 주소는 거절된다. 방법 후보가 4개 있고 직접 실행해 확인해야 한다 → [PoC-05](../poc/poc-05-docs-image.md).

## 3. 확인한 사실

### 공식 문서 (확인함)

| 내용 | 출처 |
|---|---|
| Docs API의 이미지 삽입은 "공개적으로 접근할 수 있는" 주소를 요구한다 | [Docs API Requests](https://developers.google.com/workspace/docs/api/reference/rest/v1/documents/request), [Insert inline images](https://developers.google.com/workspace/docs/api/how-tos/images) |
| 주소 길이 2kB 이하, 이미지 50MB 미만, 25메가픽셀 이하, PNG·JPEG·GIF | 같은 문서 |
| `drive.file` 권한으로 앱이 만든 폴더와 파일을 읽고 쓸 수 있다 | [Choose Google Drive API scopes](https://developers.google.com/workspace/drive/api/guides/api-specific-auth) |

공식 문서에 **없는** 내용:

- 드라이브에 있는 파일의 주소를 쓸 수 있는지
- 넣은 이미지가 문서 안에 복사되는지(원본을 지우거나 비공개로 돌려도 남는지)

### 외부 자료 (직접 확인 필요)

구글 Workspace CLI 저장소의 기능 요청 이슈에 비공개 드라이브 이미지로 시도한 결과가 정리되어 있다.

| 시도 | 결과 |
|---|---|
| 드라이브 내려받기 주소 (`drive.google.com/uc?export=download`) | 실패 (403) |
| 드라이브 API의 `thumbnailLink` | 실패 (403) |
| `drive.google.com/thumbnail?id=...` | 실패 (가져오기 오류) |
| HTML로 올려 Docs로 변환, 이미지는 base64 | 실패 (변환 중 이미지가 조용히 빠짐) |
| HTML로 올려 Docs로 변환, 이미지는 드라이브 주소 | 실패 (빈 그림 자리만 생김) |
| Apps Script로 파일을 읽어 넣기 | **성공** (사용자 권한으로 파일 내용을 직접 넣음) |

출처: [googleworkspace/cli 이슈 #856](https://github.com/googleworkspace/cli/issues/856). 한 사람의 시도 기록이다. Task Hive의 권한(`drive.file`)에서 같은 결과가 나오는지는 실행해 봐야 안다.

## 4. 방법 후보

| 방법 | 어떻게 | 사진이 공개되나 | 문서 안에 그림이 보이나 | 걱정 |
|---|---|---|---|---|
| A. 링크만 넣기 | 사진을 이미지 폴더에 올리고, Docs에는 그 파일로 가는 링크를 넣는다 | 아니오 | 아니오 (누르면 열림) | 없음. 확실히 된다 |
| B. 잠깐 공유했다가 되돌리기 | 사진을 "링크가 있는 누구나 보기"로 바꿈 → Docs에 넣음 → 바로 비공개로 되돌림 | **잠깐 공개됨** | 예 (넣은 뒤에도 남는지는 확인 필요) | 되돌리기가 실패하면 사진이 공개된 채 남는다. 주소를 아는 사람은 그 사이에 볼 수 있다 |
| C. Word 파일로 만들어 변환 | 서버에서 사진을 넣은 `.docx`를 만들어 드라이브에 올리며 Docs로 변환한다 | 아니오 | 예로 추정 (확인 필요) | 기존 문서에 덧붙일 수 없다. 월별 문서 하나에 이어 쓰는 구조와 맞지 않아 "하루 한 문서"가 된다 |
| D. Apps Script | 사용자 권한으로 도는 스크립트가 파일을 읽어 넣는다 | 아니오 | 예 | Apps Script API 설정과 추가 권한이 필요하다. 구조가 크게 복잡해진다 |

서버를 잠깐 공개 주소로 쓰는 방법(서버가 일회용 주소로 사진을 내주고 Docs API가 가져가게 함)도 생각할 수 있다. 사진이 서버를 지나가고, 그 주소가 열려 있는 동안은 공개이며, 대화·사진을 서버에 두지 않는다는 원칙(D-08)과 맞지 않아 후보에서 뺐다.

## 5. 추천

| 단계 | 추천 |
|---|---|
| 지금 (1~2단계) | **A. 링크만 넣기.** 사진은 「테스크 하이브 일기/이미지」 폴더에 올리고 Docs에는 링크를 넣는다. 개인정보 위험이 없고 확실히 된다 |
| PoC 뒤 | C가 된다면 "사진 있는 날은 하루 한 문서" 방식으로 그림을 문서 안에 넣는다 |
| 쓰지 않는 것 | B. 사진이 잠깐이라도 공개되는 방식은 "보안 최대화" 요구와 맞지 않는다 |

이 추천은 미확정이다. → [07 Q-08](../07-open-questions.md)

## 6. 폴더 구조 (제안)

```
내 드라이브/
└── 테스크 하이브 일기/          앱이 만든 폴더 (drive.file로 접근)
    ├── 2026-11                  월별 일기 (시트 또는 Docs)
    ├── 2026-12
    └── 이미지/                  앱이 만든 하위 폴더
        ├── 2026-11-17_01.jpg
        └── 2026-11-17_02.jpg
```

- 폴더와 파일을 앱이 만들기 때문에 `drive.file` 권한만으로 다룰 수 있다.
- 사용자가 드라이브 화면에서 직접 올린 사진은 앱이 만든 파일이 아니라서 `drive.file`로는 읽지 못한다(확인 필요). 사진은 Task Hive 화면에서 올리게 한다.
- 사진은 브라우저 → 서버 → 드라이브로 지나간다. 서버는 저장하지 않고 전달만 한다. 크기와 형식을 제한한다.

## 7. 함께 정할 것

| 질문 | 메모 |
|---|---|
| 어떤 이미지를 올리려는가 | 사용자가 고른 사진 / AI가 만든 그림 / 벌집 화면 캡처. 답에 따라 방법이 달라진다 |
| 시트 일기에도 이미지를 넣을까 | 시트의 `IMAGE()` 함수도 공개 주소가 필요하다(외부 자료). 시트는 링크만 넣는 것을 추천 |
| 사진에 들어 있는 위치 정보 | 올리기 전에 지울지 정한다. 지우는 것을 추천 |

## 8. 아직 확인하지 못한 것

[PoC-05](../poc/poc-05-docs-image.md)에서 확인한다.

- `drive.file` 권한에서 방법 A~C가 실제로 되는지
- 방법 B에서 넣은 뒤 비공개로 되돌려도 그림이 남는지
- 방법 C에서 `.docx` 안의 사진이 변환 뒤에도 남는지
- 사용자가 드라이브에서 직접 올린 사진을 앱이 읽을 수 있는지
