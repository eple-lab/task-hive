# 02. 결정 기록

작성일: 2026-11-17

- **확정**: eple이 2026-11-17에 답한 것
- **제안**: Claude의 추천. eple이 정하기 전까지 구현하지 않는다 → [07 열린 질문](07-open-questions.md)

## 1. 확정한 결정

### D-01. 백엔드는 Python FastAPI

- 고른 것: Python FastAPI
- 다른 후보: Node/Express (`todo` 방식)
- 이유: `llm-chatbot`의 SSE 스트리밍 프록시와 `honey-voice-log`의 구글 로그인·토큰 암호화·Neon·시트 저장이 모두 FastAPI다. 두 프로젝트의 구조를 그대로 본받을 수 있다.
- 영향: `todo`의 규칙과 테스트는 코드가 아니라 **규칙 목록**으로 가져온다.

### D-02. 태스크 원본은 Neon, 구글 시트는 사본

- 고른 것: Neon Postgres가 원본. 벌집 등록·체크 때 사용자의 구글 시트로 한 방향 내보내기
- 다른 후보: 구글 시트가 원본 / 양방향 동기화
- 이유: 충돌 처리가 없고 화면이 빠르다. 시트 API 호출 한도에 덜 걸린다.
- 감수하는 것: 서버 DB에 태스크 제목이 남는다. 그래서 제목을 암호화해 저장하는 안을 제안한다(P-03).
- 영향: "task-hive todo 구글시트 가기"로 연 시트에서 고친 내용은 앱에 반영되지 않는다. 시트 첫 줄에 이 사실을 적는다.

### D-03. TTS는 Colab 모델 우선, 브라우저 내장 음성으로 대체

- 고른 것: Colab에 TTS 모델을 함께 올린다. Colab이 꺼져 있으면 브라우저 내장 음성(Web Speech API)으로 읽는다.
- 다른 후보: 브라우저 내장 음성만 / Colab TTS만
- 이유: 에코 효과는 서버에서 받은 음성 데이터에만 걸 수 있다(Web Audio). 브라우저 내장 음성은 소리를 가공할 수 없다. 메인 퀘스트의 "음성 생성 모델 직접 실행"도 충족한다.
- 영향: 대체 음성일 때는 에코·저음 설정 일부가 적용되지 않는다. 화면에 "기본 음성으로 읽는 중"을 표시한다.

### D-04. ngrok URL은 사용자마다 자기 것을 넣는다

- 고른 것: 각 사용자가 자기 Colab 주소를 넣고 자기 세션에만 적용
- 다른 후보: 관리자만 전체 적용 / 환경변수로만
- 이유: README의 노트북 사용법대로 각자 개인 Colab으로 LLM을 돌리게 하려는 것이다. 대화가 서비스 운영자의 LLM이 아니라 **본인 Colab**으로만 간다.
- 감수하는 것: 서버가 사용자가 준 주소로 요청을 보내므로 SSRF 방어가 필수다. → [05 보안 5장](05-security.md)
- 영향: 주소가 없거나 연결이 안 되면 대화는 꺼지고 벌집·직접 체크만 동작한다.

### D-05. 초안의 구독·결제·광고는 로드맵 단계로 포함

- 고른 것: 구독, 카카오 로그인, 카카오페이, 5초 광고, 7개 제한, 로컬 SQLite를 로드맵 뒤 단계에 정식으로 둔다.
- 다른 후보: 백로그로만 / 폐기
- 영향: 아키텍처에 인증 수단 추가와 결제 모듈이 들어갈 자리를 남긴다. → [03 아키텍처 9장](03-architecture.md)

### D-06. 벌집은 2D SVG/CSS 먼저

- 고른 것: 육각형 벌집, 꿀 채우기, 벌 비행, 클로즈업을 SVG와 CSS 애니메이션으로 만든다. Three.js 3D는 뒤 단계.
- 다른 후보: 처음부터 Three.js / 2D Canvas
- 이유: 구형 기기에서도 가볍다. 칸마다 실제 요소라서 클릭, 키보드 조작, 화면 낭독기, 테스트가 쉽다.

### D-07. 손님 데이터는 세션 ID로 저장, 내려받기 직후 + 24시간 뒤 삭제

- 고른 것: 무작위 세션 ID 행으로 Neon에 잠깐 저장한다. 내려받으면 즉시, 아니면 마지막 활동 24시간 뒤 지운다.
- 다른 후보: 브라우저에만 두고 서버 저장 없음 / 세션 종료 즉시 삭제
- 이유(eple): "db는 저장만 하고 출력 후 삭제". 새로고침해도 이어 갈 수 있다.
- 풀이: 손님은 사람이 아니라 브라우저 쿠키의 세션 ID로만 구분한다. 24시간 삭제는 누구인지 몰라도 "마지막 활동 시각이 24시간 지난 손님 행"을 지우는 방식이다. 쿠키를 잃으면 그 데이터는 다시 볼 수 없고 24시간 뒤 지워진다.

### D-08. 대화 원문은 서버에 보관하지 않는다

- 고른 것: 대화는 브라우저 세션에만 둔다. 서버는 중계만 한다.
- 다른 후보: 당일분만 암호화 보관 / 계속 보관
- 이유: 일기와 속마음이 담기는 가장 민감한 데이터다. 없는 데이터는 유출되지 않는다.
- 영향: 새로고침하면 대화가 사라진다. 남는 것은 등록한 태스크(Neon)와 사용자가 승인한 일기 요약(본인 구글 드라이브)뿐이다. 서버 로그에도 대화 본문을 남기지 않는다.

### D-09. 성능 검토 화면은 운영 지표 + PoC 검증

- 고른 것: 응답 속도·TTS 지연·오류율·외부 API 상태와, 메인 퀘스트용 검증 탭(할 일 추출 정확도, 수작업 대비 시간)을 함께 둔다.
- 다른 후보: 운영 지표만 / 모든 사용자에게 공개
- 전제: 대화 내용은 담지 않고 숫자만 모은다.

### D-10. 말로 입력하기(STT)는 2단계에 Colab Whisper로

- 고른 것: 1단계는 글 입력 + TTS. 2단계에 마이크 버튼과 Colab Whisper를 붙인다.
- Render 무료에서 가능한 이유: Whisper는 Colab GPU에서 돈다. Render는 녹음 파일을 전달만 하므로 512MB 안에 들어간다. `honey-voice-log`가 Render에 못 올라간 것은 Whisper를 서버 안에서 돌렸기 때문이다.
- 영향: STT → LLM → TTS 파이프라인이 되어 과제 가산 요소를 충족한다.

### D-11. 캘린더는 지난 7일 + 앞으로 30일

- 고른 것: 오늘 기준 -7일 ~ +30일
- 다른 후보: 앞으로 30일만 / 이번 달 1일~말일
- 이유: 지난 일정은 "그건 하셨어요?"를 조심스럽게 물을 근거가 된다.

### D-13. Colab은 과제용 실험 환경

- 고른 것: Colab은 과제용이다. LLM이 텍스트(대화)를 요약할 수 있는지 테스트하는 데 쓴다.
- 배경: Colab FAQ가 대화형 연산과 관련 없는 웹 서비스 제공을 제한한다([checks/colab-usage.md](checks/colab-usage.md)).
- 영향: 계속 켜 두는 서비스의 기반으로 쓰지 않는다. README와 연결 화면에 "과제용 실험 환경, 세션이 끊길 수 있음"을 적는다. 실험 계획은 [PoC-01](poc/poc-01-llm-summary.md).

### D-14. 캘린더는 사용자가 소유한 캘린더만, 켜고 끌 수 있게

- 고른 것: 권한은 `calendar.events.owned.readonly`(내가 소유한 캘린더의 일정 보기). 캘린더 기능은 사용자가 켜거나 끌 수 있다.
- 다른 후보: `calendar.events.readonly`(볼 수 있는 모든 캘린더)
- 이유(eple): 로그인을 사용자 본인이 하므로 본인 소유 캘린더만 보면 된다.
- 영향: 공유받은 남의 캘린더는 읽지 않는다. 기능을 켤 때 권한을 요청하고, 꺼져 있으면 캘린더를 읽지 않는다. P-01의 캘린더 권한을 이것으로 바꾼다.

### D-15. 일기의 구글 시트·Docs 사용도 켜고 끌 수 있게

- 고른 것: 일기를 구글 시트나 Docs에 저장하는 기능을 사용자가 켜거나 끌 수 있다.
- 영향: 꺼져 있으면 드라이브에 쓰지 않고, 일기 버튼은 "일기 내려받기(MD)"가 된다. 켤 때 드라이브 권한을 요청한다.
- 덤: 구글 기능을 모두 끈 로그인 사용자는 `openid`만 쓰므로 7일 토큰 만료와 테스트 사용자 등록 대상이 아니다([checks/google-oauth-7day-expiry.md](checks/google-oauth-7day-expiry.md)).

### D-12. 그 밖에 eple이 처음부터 정한 것

| 결정 | 내용 |
|---|---|
| 클라우드 | Neon + Render 무료 버전 |
| LLM 위치 | Colab + ngrok. 각자 개인 Colab으로 돌릴 수 있게 노트북 사용법을 README에 넣는다 |
| 로그인 | 구글 로그인 또는 이름만 적는 손님 모드 |
| 화면 | 왼쪽 하이브 · 가운데 채팅 · 오른쪽 상태창, 양쪽 접기 |
| 기본 언어 | 한국어 |
| 일기 저장처 | 구글 시트 또는 구글 Docs 중 선택 |
| 문서 | 프로젝트 `docs/` 폴더의 마크다운 |

## 2. 제안 (미확정)

구현 전에 eple이 정한다. 각 항목의 선택지는 [07 열린 질문](07-open-questions.md)에 있다.

| P-01 | 구글 권한은 `openid` + `drive.file` + `calendar.events.owned.readonly`(D-14로 확정)만. 처음에는 `openid`만 받고, 기능을 켤 때 그 권한을 따로 요청 | 필요한 만큼만, 필요한 순간에 받는다 | Q-01 |
| P-02 | 구글 이메일·이름·프로필 사진을 받지 않는다. 구글 사용자 ID는 HMAC으로 가려 저장하고, 부를 이름은 사용자가 적는다 | `honey-voice-log`에서 검증한 방식. 유출돼도 누구인지 알기 어렵다 | Q-01 |
