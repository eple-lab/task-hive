## 1. 한 줄 정의

저녁에 자기 전 일기를 쓰듯 AI와 편하게 대화하면, AI가 할 일을 끌어내 벌집(하이브)에 쌓아 주고 오늘의 일기를 내 구글 드라이브에 남겨 주는 서비스.

## 2. 배경과 과제 조건

- AIFFEL 「AI 이해하고 사용하기」 메인 퀘스트 2(내 도메인에서 AI 개선 지점을 찾아 PoC 만들기)의 결과물이다.
- 과제가 요구하는 것: 문제 정의서, AI 모델 1개 이상 직접 실행, 입력 → AI 처리 → 결과 출력이 이어지는 PoC, 기존 방식과의 비교 검증(실패 사례 포함), 재현 가능한 README.
- 과제 가산 요소: 여러 모델을 한 파이프라인으로 엮기, 데모 배포, 실패 사례 정리, 다음 단계 제안.
- 지금까지 배우며 만든 프로젝트를 조합한다.

| 가져올 것 | 출처 프로젝트 |
|---|---|
| 할 일·하위 태스크 규칙, 검증 규칙, 테스트 방식 | `todo` |
| Colab vLLM + ngrok 스트리밍 프록시 | `llm-chatbot` |
| 구글 로그인, 토큰 암호화, Neon, 시트 저장, 손님 모드 | `honey-voice-log` |

## 4. 실행 환경

- [확정] 클라우드는 Neon(DB)과 Render(서버) 무료 버전을 쓴다.
- [확정] 로컬에서도 실행할 수 있어야 하고, 로컬 실행 순서를 문서로 정의한다. → [03 아키텍처 8장](03-architecture.md)
- [확정] LLM은 Colab에 올리고 ngrok으로 연결한다.
- [확정] README에 노트북 사용법을 넣어, 각자 개인 Colab 계정으로 노트북을 돌려 자기 LLM을 쓸 수 있게 한다.
- [확정] 서버 DB에는 데이터를 최대한 쌓지 않는다.

| 번호 | 요구사항 | 상태 |
|---|---|---|

| R-CHAT-5 | 모든 대화는 채팅창에 동일하게 적힌다. 상태창에서 일어난 선택·등록도 채팅창에 남는다 | 확정 |
| R-CHAT-6 | 한국어가 기본이고 한국어를 잘해야 한다. 주요 국가 언어로 바꿀 수 있다 | 확정 |

| R-CHAT-8 | 완료 여부와 하위 태스크 진행은 사용자의 심기를 거스르지 않게 조심해서 묻는다 | 확정 |
| R-CHAT-9 | 사용자가 "그건 한 것 같아"라고 하면 해당 태스크의 체크박스를 체크한다. 하위 태스크가 있는 경우와 없는 경우를 나눠 처리한다 | 확정 |
| R-CHAT-10 | 대화 원문은 서버에 보관하지 않는다. 브라우저 세션에만 있고 새로고침하면 사라진다 | 확정 |
| R-CHAT-11 | 말로 입력하기(STT)는 2단계에서 Colab Whisper로 붙인다 | 확정 |

R-CHAT-9의 세부 동작(제안):

| 상황 | 동작 |
|---|---|
| 하위 태스크가 없는 태스크 | 태스크를 완료로 체크한다 |
| 하위 태스크가 있고 사용자가 특정 항목을 말함 | 그 하위 태스크만 체크한다 |
| 하위 태스크가 있고 "다 했어"라고 말함 | 남은 하위 태스크 목록을 보여 주고 전부 체크할지 확인한 뒤 체크한다 |
| 어느 태스크인지 애매함 | 후보 2~3개를 보여 주고 고르게 한다 |
| 체크한 직후 | 채팅창에 무엇을 체크했는지 적고 "되돌리기"를 제공한다 |

### 5.5 할 일 모으기와 벌집 등록

| 번호 | 요구사항 | 상태 |
|---|---|---|
| R-HIVE-1 | 상태창에 후보 목록을 보여 준다 | 확정 |
| R-HIVE-2 | 대화하면서 사용자가 올리기로 한 항목을 "하이브 등록 예정" 목록으로 보여 준다 | 확정 |
| R-HIVE-3 | 목록 아래에 "지금까지 모은 task 벌집으로 옮기기" 버튼을 두어 바로 등록할 수 있다 | 확정 |
| R-HIVE-4 | 등록하면 꿀통을 든 벌이 나타나 멀리 있는 벌집으로 날아가고, 이어서 벌집을 클로즈업해 보여 준다 | 확정 |
| R-HIVE-5 | 등록한 태스크 수만큼 벌집 칸이 생긴다. D-day가 있는 칸과 없는 칸이 있다 | 확정 |
| R-HIVE-6 | 태스크는 하위 태스크를 가진다. 규칙은 `todo` 프로젝트 기준이다 | 확정 |
| R-HIVE-7 | 하이브는 채팅창 왼쪽에 있다. 하단에 "task-hive todo 구글시트 가기" 버튼이 있어 사용자의 구글 시트를 연다 | 확정 |
| R-HIVE-8 | 태스크 원본은 Neon이고, 구글 시트는 한 방향으로 내보낸 사본이다. 시트에서 고친 내용은 앱에 반영되지 않는다 | 확정 |
| R-HIVE-9 | 벌집과 벌 애니메이션은 2D SVG/CSS로 먼저 만든다. Three.js 3D는 뒤 단계다 | 확정 |

`todo` 프로젝트에서 이어받는 규칙(확정 R-HIVE-6의 풀이, 세부는 제안):

- 태스크 제목은 중복할 수 없다. 하위 태스크 제목은 같은 태스크 안에서만 중복할 수 없다.
- 제목은 비울 수 없고 길이 제한이 있다(`todo`는 200자).
- 안 끝난 하위 태스크가 있는 태스크를 완료하거나, 하위 태스크가 있는 태스크를 지울 때는 확인받는다.
- 같은 규칙을 화면, 서버, DB 세 곳에서 검사한다.
- 달라지는 점: `todo`는 마감일이 필수지만 Task Hive는 **D-day 없는 태스크를 허용한다**(R-HIVE-5).

## 7. 비기능 요구사항

| 영역 | 요구사항 | 상태 |
|---|---|---|
| 보안 | 개인정보, 계정 정보, 태스크, 일기에 대한 보안을 최대화한다. DevSecOps로 운영한다 | 확정 |
| 데이터 최소화 | 서버 DB에 최대한 쌓지 않는다. 대화 원문은 보관하지 않는다 | 확정 |
