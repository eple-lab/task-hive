# 검증 자료 (PoC-01)

> **초안 작성: Claude (2026-11-17). eple 검토 전이다.** 말투와 정답을 eple이 읽고 고친 뒤에 모델을 돌린다.

LLM이 저녁 대화에서 할 일을 잘 뽑는지 재는 데 쓰는 **가상 대화**와 **미리 적은 정답**이다. 실험 계획은 [docs/poc/poc-01-llm-summary.md](../../docs/poc/poc-01-llm-summary.md).

## 지킨 규칙

- **가상의 인물과 상황만** 썼다. 실제 일기, 실제 일정, 실제 사람 이름이 없다.
- **정답은 모델을 돌리기 전에 적었다.** 결과를 보고 정답을 고치지 않는다. 정답이 틀렸다고 판단되면 고친 이유와 날짜를 아래 "고친 기록"에 적고, 그 뒤의 측정부터 새 정답을 쓴다.
- 기준 날짜는 모두 `2026-11-17`(화요일)이다. 정답의 날짜는 이 날짜에서 계산했다.

## dialogs.jsonl 구성

| 종류 (`category`) | 뜻 | 건수 | id |
|---|---|---|---|
| `plain` | 평범한 대화, 할 일 1~2개 | 10 | d01~d10 |
| `none` | 할 일이 없는 대화 | 3 | d11~d13 |
| `negation` | 하지 않기로 했거나 취소된 일 | 2 | d14~d15 |

- 기대하는 할 일은 모두 19개다.
- 어려운 것(`hard: true`)은 8건이다: d12, d14~d20.

### 어려운 것이 어려운 이유

| id | 함정 |
|---|---|
| d12 | 발표와 자료 제출은 이미 끝난 일이다. 뽑으면 안 된다 |
| d14 | "보고서 수정"은 취소됐다. "회의 자료 인쇄"만 뽑아야 한다 |
| d15 | 대청소는 하지 않기로 했다. 아무것도 뽑으면 안 된다 |
| d16 | 짐 싸기와 인터넷 이전은 동생의 일이다 |
| d17 | 수리 기사 부르기는 룸메이트의 일이다. "책 반납"만 뽑아야 한다 |
| d18 | "이번 달 말"을 2026-11-30으로 바꿔야 한다 |
| d19 | "다음 주쯤"은 정해지지 않은 날짜다. 날짜를 지어내지 않고 비워야 한다 |
| d20 | 여행 준비 하나에 하위 태스크 3개다. 따로 3개를 뽑으면 구조 오류다 |

### 한 줄의 모양

```json
{
  "id": "d01",
  "category": "plain",
  "today": "2026-11-17",
  "messages": [{"role": "assistant", "content": "..."}, {"role": "user", "content": "..."}],
  "expected": {
    "tasks": [
      {"title_keywords": ["치과|병원", "예약|전화"], "due_date": "2026-11-18", "subtasks_keywords": []}
    ],
    "summary_points": ["회사에서 바빴다", "이가 시려 치과 예약이 필요하다"]
  },
  "hard": false,
  "note": ""
}
```

### 정답을 키워드로 적은 이유

모델마다 "치과 예약", "치과에 전화하기"처럼 표현이 다르다. 제목이 글자 그대로 같은지 보면 맞는 답도 틀렸다고 나온다. 그래서 키워드가 들어 있는지로 채점한다.

- `title_keywords`의 각 항목은 **모두** 들어 있어야 한다.
- 항목 안의 `|`는 **또는**이다.
- 예: `["치과|병원", "예약|전화"]` = (치과 또는 병원) 그리고 (예약 또는 전화)
- 공백과 대소문자는 무시한다.
- `subtasks_keywords`도 같은 방식이다. 하위 태스크 하나에 키워드 묶음 하나다.
- `due_date`가 `null`이면 "날짜가 없어야 맞다"는 뜻이다.

키워드가 너무 느슨하면 틀린 답이 맞다고 나오고, 너무 빡빡하면 맞는 답이 틀렸다고 나온다. 결과 `.md`의 "대화별" 표에서 사람이 한 번 훑어본다.

`summary_points`는 요약에 꼭 들어가야 할 사건이다. 자동으로 채점하지 않고 사람이 읽고 판정한다.

## completions.jsonl 구성

| id | 상황 | 기대 |
|---|---|---|
| c01 | 하위 태스크 없는 태스크를 끝냈다고 말함 | 그 태스크 |
| c02 | 하위 태스크 하나를 끝냈다고 말함 | 그 하위 태스크 |
| c03 | "다 끝냈어" | 태스크 + `all_subtasks: true` (확인받아야 하는 경우) |
| c04 | "그건 한 것 같아"만 말함 | 없음 (무엇인지 알 수 없다) |
| c05 | "아직 못 했어" | 없음 |
| c06 | 태스크와 관계없는 말 | 없음 |
| c07 | "납부"를 "이체"로 바꿔 말함 | 그 태스크 |
| c08 | 하위 태스크를 다른 말로 표현 | 그 하위 태스크 |
| c09 | 동생이 한 일 | 없음 (남의 일) |
| c10 | 내일 할 계획 | 없음 (아직 안 했다) |

기대값은 `task_id`, `subtask_id`, `all_subtasks` 세 값이고, 세 값이 모두 같아야 맞은 것으로 센다.

## eple이 검토할 때 볼 것

- 말투가 실제 저녁 대화와 비슷한가. 어색한 문장은 고친다.
- 정답에 동의하는가. 특히 d03(선물 주문 기한을 목요일로 봄), d06("토요일 전까지"를 토요일로 봄), d09(회의록 "정리"는 끝난 일로 봄), d10·d19(날짜 없음으로 봄).
- 실제로 자주 하는 말인데 빠진 종류가 있는가. 있으면 대화를 더한다.
- 키워드가 너무 느슨하거나 빡빡한 곳이 있는가.
