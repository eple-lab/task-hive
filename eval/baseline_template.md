# 기준선 기록: todo 앱에 손으로 입력

AI를 넣기 전 방식이 얼마나 걸리고 얼마나 놓치는지 잰다. 이 숫자가 있어야 Task Hive가 나아졌는지 말할 수 있다. 기준선이 더 좋게 나오면 그것도 결과다.

## 재는 방법

1. `eval/samples/dialogs.jsonl`의 대화를 **정답을 가리고** 읽는다. (`messages`만 본다. 결과 `.md`의 "대화별"을 쓰면 정답이 보이니 쓰지 않는다)
2. 대화를 다 읽은 순간부터 시간을 잰다.
3. 직접 만든 `todo` 앱에 할 일, 마감일, 하위 태스크를 넣는다.
4. 다 넣으면 시간을 멈춘다.
5. 넣은 것을 정답(`expected.tasks`)과 비교해 놓친 개수와 잘못 넣은 개수를 적는다.

- 같은 사람이 Task Hive와 기준선을 모두 재면, 두 번째에는 내용을 이미 알아 빨라진다. 절반은 기준선을 먼저, 절반은 Task Hive를 먼저 잰다.
- 시간은 초 단위로 그대로 적는다. 반올림하지 않는다.
- 20건을 다 재기 어려우면 잰 건수만 적고, 못 잰 것은 비워 둔다. 지어내지 않는다.

- 쓴 앱과 주소: 직접 만든 `todo` 앱

- 시간은 **20건 전체를 한 번에** 쟀다. 대화별 시간은 없다. 마감일은 대화를 보고 계산해 넣었다(eple).
- **날짜는 비교에서 뺀다.** 자료는 20건 모두 "오늘 = 2026-11-17"인데, eple은 대화 하나를 하루씩 뒤(d01 = 11-17, d02 = 11-18, …)로 읽고 계산했다. 읽기용 파일이 맨 위에 한 줄로만 오늘 날짜를 적어 놓친 탓이다(이후 대화마다 적도록 고침). 그 기준으로 다시 맞춰 보면 d03 한 건을 빼고 계산이 맞는다. 또 `todo` 앱은 마감일이 기본으로 들어가야 해서, 날짜가 없는 일(d10, d19)에는 대략 정한 날짜를 넣었다(eple). 그래서 아래 "날짜 틀린 수" 칸은 정답 날짜와 비교한 참고값일 뿐이다.

## 합계에서 낼 숫자

| 항목 | 계산 | 값 |
|---|---|---|
| 놓치지 않은 비율 | (19 - 놓친 수 합) / 19 | **1.00** (19 / 19) |
| 잘못 넣은 수 | 합계 | **3** (모두 할 일이 아닌 일정). 따로: 하위 태스크를 따로 넣은 구조 차이 1건(3개) |
| 대화 한 건당 시간(초) | 시간 합 / 잰 건수 | **69** (1,380 / 20) |
| 할 일 한 개당 시간(초) | 시간 합 / 넣은 할 일 수 합 | **53** (1,380 / 26) |
